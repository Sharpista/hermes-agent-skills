# Reflect

Esta skill é uma revisão de processo, não uma licença para criar documentação. Examine cartões, handoffs, falhas de validação e feedback recentes. Procure um padrão repetido que tenha custo ou risco mensurável.

Avalie cada candidato por frequência, custo, risco, estabilidade do padrão e cobertura atual. Prefira, nesta ordem:

1. corrigir a instrução existente;
2. adicionar uma referência pequena;
3. criar uma skill especializada;
4. alterar o fluxo ou ferramenta apenas quando o problema não for instrucional.

Se a evidência for fraca, registre “nenhuma mudança”. Quando houver mudança, escreva o problema observado, a evidência, a menor intervenção escolhida e como medir se ela funcionou. Não copie uma skill externa inteira nem altere perfis por preferência estética.

Para mudanças no Hermes, preserve o contrato Kanban, a fonte canônica em `shared/agent-skills` e a validação existente. Peça revisão do usuário antes de transformar uma hipótese de processo em regra global.
